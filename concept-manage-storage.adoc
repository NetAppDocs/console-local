= Understanding storage management in NetApp Console (local)
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
// Jira: SPSPM-3309

NetApp Console (local) helps you manage ONTAP storage at scale using consistent, reusable standards. Instead of making one-off decisions for every volume or LUN, you define approved behavior once and apply it across fleets—whether you provision manually, use automated placement, or use AI-assisted plan-and-approve workflows.

== How storage management works

NetApp Console (local) connects four concepts into one workflow:

. *Fleets* define the scope where you manage storage. A fleet groups systems so you can control access, apply standards consistently, and manage resources as a unit.
. *Storage class policies* define standards as reusable building blocks (performance, capacity, security, data protection).
. *Storage classes* express workload intent. A storage class is a named template assembled from one ore more policies.
. *Provisioning workflows* create storage within guardrails. Different workflows make configuration decisions differently, but all can enforce storage classes and remain governed by RBAC and audit logging.

== Why a standards-based approach helps

Using storage classes and policies helps you:

. *Reduce decision fatigue*: provision by selecting an approved class instead of tuning many parameters.
. *Increase consistency*: new workloads start from the same baseline across teams and fleets.
. *Scale safely*: standards can be applied via runbooks, automation, or AI-assisted workflows without losing governance.
. *Detect and remediate drift*: workloads can be monitored against class expectations and corrected when they fall out of compliance.

== Typical workflow

1. Discover storage systems into the correct fleet or fleets.
2. Define storage class policies that represent your standards.
3. Create storage classes by combining policies into workload templates.
4. Associate storage classes with the fleets where they apply.
5. Provision volume or LUNs using the method that matches your operational model.
6. Operate day-2 with monitoring, alerting, drift detection, and remediation.

== Choose how you want to provision

NetApp Console (local) supports multiple provisioning workflows so you can match your operational model while still enforcing storage class standards.

* *Manual provisioning* — You choose the target system and configuration details. Use when you need explicit control over system selection and configuration details.
link:task-provisioning-manual.html[Provision storage manually in NetApp Console (local)]

* *Automated provisioning* — You provide workload inputs and (optionally) a storage class. NetApp Console (local) recommends best-fit placement and applies class-driven settings to reduce manual decisions and drift risk.
link:task-provisioning-automated.html[Provision storage automatically in NetApp Console (local)]

* *AI-assisted (agentic) provisioning* — You describe what you need in natural language. NetApp Console (local) proposes a plan constrained by RBAC and storage classes, then provisions only after you review and approve the plan.
link:task-provisioning-agentic.html[Provision storage with agentic workflows in NetApp Console (local)]
