= Learn about managing storage with NetApp Console (local deployment)
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
// Jira: SPSPM-3309

NetApp Console (local deployment) helps you manage ONTAP storage at scale using consistent, reusable standards. Instead of making one-off decisions for every volume or LUN, you define approved behavior once and apply it across fleets—whether you provision manually, use automated placement, or use AI-assisted plan-and-approve workflows.

Storage management is the practice of defining storage standards, applying them consistently, and operating workloads so they stay aligned over time. In Console (local deployment), those standards are expressed as storage class policies and storage classes, scoped to fleets, and enforced through provisioning workflows governed by RBAC and audit logging.

== How storage management works

Console (local deployment) connects four concepts into one workflow:

. *Fleets* define the scope where you manage storage. A fleet groups systems so you can control access, apply standards consistently, and manage resources as a unit.
. *Storage class policies* define standards as reusable building blocks (performance, capacity, security, data protection).
. *Storage classes* express workload intent. A storage class is a named template assembled from one ore more policies.
. *Provisioning workflows* create storage within guardrails. Different workflows make configuration decisions differently, but all can enforce storage classes and remain governed by RBAC and audit logging.

== Why a standards-based approach helps

Using storage classes and policies helps you:

. *Reduce decision fatigue* by provisioning from approved options instead of tuning many parameters.
. *Increase consistency* so new workloads start from the same baseline across teams and fleets.
. *Scale safely* by applying standards via runbooks, automation, or AI-assisted workflows without losing governance.
. *Detect and remediate drift* by monitoring workloads against class expectations and correcting noncompliance.

== Provisioning approaches

Console (local deployment) supports multiple provisioning approaches. They differ mainly in how placement and configuration decisions are made, but all remain governed by RBAC, audit logging, and (when selected or required) storage class standards.

* *Manual provisioning* — You select the target system and specify configuration details directly. Use manual provisioning when you need explicit control over system selection and configuration inputs.
link:task-provisioning-manual.html[Provision storage manually in NetApp Console (local deployment)]

* *Automated provisioning* — You provide workload inputs and optionally select a storage class. Console (local deployment) recommends best-fit placement and applies class-driven settings to reduce manual decisions and configuration variance.
link:task-provisioning-automated.html[Provision storage automatically in NetApp Console (local deployment)]

* *AI-assisted (agentic) provisioning* — You describe what you need in natural language. Console (local deployment) proposes a plan constrained by RBAC and storage classes, then provisions only after you review and approve the plan.
link:task-provisioning-agentic.html[Provision storage with agentic workflows in NetApp Console (local deployment)]
