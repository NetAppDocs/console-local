= Storage management in NetApp Console (local)
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
// Jira: SPSPM-3309

NetApp Console (local) is designed to help you run storage with consistent standards at scale. Instead of making one-off decisions for every volume or LUN, you define approved storage behavior once and apply it repeatedly across fleets—whether you provision manually, through automation, or with AI-assisted workflows.

This section helps you understand storage management in NetApp Console (local), including how to define storage standards, apply them during provisioning, and choose the right provisioning method for your environment.

== How storage management works in NetApp Console (local)

NetApp Console (local) connects four ideas into one workflow:

. *Fleets* define where you manage storage. Fleets group storage systems so you can scope access, apply standards consistently, and manage resources as a unit.
. *Storage classes* define the desired behavior for workloads. A storage class is a named template that represents the desired behavior for volumes and LUNs.
. *Storage class policies* define the building blocks of a storage class. Policies let you standardize specific dimensions (performance, capacity, security, and data protection) and reuse those standards across multiple classes.
. *Provisioning workflows* define how storage gets created—with full manual control, automated best-fit placement, or conversational AI-assisted planning and execution.

== What you get from a standards-based approach

Using storage classes and policies helps you:

. *Reduce decision fatigue*: operators provision storage by choosing an approved class instead of configuring many individual parameters.
. *Improve consistency*: workloads start with the same baseline settings across fleets and across teams.
. *Scale operations*: standard definitions can be applied by junior admins, runbooks, or automation—without losing governance.
. *Set up for governance*: class-based provisioning makes it easier to detect configuration drift and respond consistently over time.

== Typical workflow

1. Define policies that represent your organization’s storage standards (for example performance targets, capacity behavior, security requirements, and snapshot schedules).
2. Assemble storage classes by combining policies into templates that match workload categories (for example “Production general,” “Database logs,” “Cost-optimized NAS”).
3. Associate storage classes with fleets where those standards should be used.
4. Provision storage using the method that matches your operational model (manual, automated, or agentic).
5. Operate day-2 using monitoring, alerts, and remediation (covered later in the Storage management section).
