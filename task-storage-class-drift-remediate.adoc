= Remediate storage class drift
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Use the Alerts workflow to review drift details for a workload and restore compliance with its assigned storage class.

== Before you begin

* Verify you have access to the fleet that contains the workload.
* Verify your role permits remediation actions (for example, Storage admin for that fleet).

== Find drift-related alerts for a storage class

. Go to *Storage classes*.
. In the *Drifts* column, select *View* for the relevant storage class.
+
Console opens the *Alerts* page with filters applied.

. Select an alert name to open the alert details page.

== Analyze the drift

. On the alert details page, select *Analyze*.
. Review the drift findings.
. For configuration drift findings, compare *intended* vs *actual* settings to understand what changed.

== Remediate

. On the alert details page, select the recommended action (for example, *Fix it* if available).
. Review the proposed change and proceed only after you understand the expected impact.

[NOTE]
====
Some remediations can be applied in place. Others may require aligning the workload to a different storage class to restore the intended behavior. Console indicates expected impact during the remediation flow.
====

== Verify compliance

After remediation completes, confirm that the workload returns to a compliant state after the next evaluation cycle. If the issue persists, re-open *Analyze* to see whether additional findings remain.

== Troubleshooting

* *No remediation action is available:* The issue may require a different remediation path (for example, updating the workload's storage class) or you may not have sufficient permissions.
* *Status does not update immediately:* Compliance evaluation may take several minutes to reflect recent changes.
