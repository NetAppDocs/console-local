= Remediate storage class drift
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Restore a workload to compliance with its assigned storage class by reviewing drift details and applying guided remediation (when available).

== Before you begin

* Verify you have access to the fleet that contains the workload.
* Verify your role permits remediation actions (for example, Storage admin for that fleet).

== Find a drifted workload

You can typically start from either entry point (availability depends on your deployment and permissions):

* *Fleets:* Open the fleet and go to *Drift / Compliance* to review workloads flagged for drift.
* *Alerts:* Open the relevant alert and select *Analyze* to review details for a single workload.

== Analyze the drift

. Open the affected workload and select *Analyze*.
. Review the findings for *configuration drift*:
+
* Compare *intended* vs *actual* settings.
* Identify which setting change caused the drift (for example, snapshots disabled or encryption turned off).

== Fix the drift

. If a guided action is available, select *Fix it*.
. Review the proposed change, then proceed only after you understand the expected impact.

[NOTE]
====
Some remediations can be applied in place. Others may require aligning the workload to a different storage class to restore the intended behavior. Console indicates expected impact during the Fix it flow.
====

== Confirm the workload is compliant

After remediation completes, confirm that the workload returns to a compliant state after the next evaluation cycle. If the issue persists, re-open *Analyze* to check for additional findings.

== Troubleshooting

* *Fix it is not available:* You might not have sufficient permissions, or the issue might require a different remediation path (for example, updating the workload's storage class).
* *Status does not update immediately:* Compliance evaluation may take several minutes to reflect recent changes.
