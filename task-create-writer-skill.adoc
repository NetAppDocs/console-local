= Create a personal GitHub Copilot skill in VS Code
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Create a personal skill with GitHub Copilot in VS Code to support a focused technical writing task across repositories and branches.

Personal skills are stored on your local computer and are not tracked or published with the documentation repository on GitHub.

NOTE: Keeping the skill on your local computer helps prevent private references, instructions, and operational details from being exposed through a public repository. The skill remains untracked only while it stays outside the repository.

A skill is a set of instructions that tells GitHub Copilot how to handle a particular type of request. This topic uses a skill called `user-focused-examples` as an example.

The examples that use `user-focused-examples` illustrate how a skill can be created, invoked, and reviewed. They do not teach the user-focused examples writing method.

== Understand personal skills and custom agents

Skills and agents both customize how Copilot works, but they support different needs.

Use a skill when you have a repeatable writing task you want to use across topics or repositories. A skill provides focused instructions and can include supporting resources, such as examples, documentation references, and terminology guidance. You can use a skill in two ways: Copilot loads it automatically when your prompt is specific enough to match its description, or you can select it from the slash-command list.

Use a custom agent when you need a broader role or workflow. An agent can define how Copilot approaches a larger task, such as reviewing a topic, coordinating several checks, or applying a consistent documentation role. Use an agent when the work requires multiple capabilities, tools, or decision points rather than one focused writing action.

You can use them together. For example, a documentation-review agent can review an entire topic and invoke a user-focused examples skill for sections that need user-goal context. Keep the skill focused on its specialized task and let the agent coordinate the larger workflow.

.Before you begin

Make sure that you:

* Have VS Code installed with GitHub Copilot enabled.
* Gather resources for the skill, such as documentation pages, terminology guidance, and examples of the content it should create.
* Identify the information that the skill must not invent, such as unsupported product behavior, metrics, or outcomes.
* Define the writing task that the skill should support.

A skill works best when it addresses one specific task, such as creating user-focused examples, or suggesting cross-reference opportunities for a new topic.

Keep the resources available while you develop the skill. You can link to supporting guidance, such as documentation URLs, content standards, or terminology guidance, from reference files under the skill's `references` directory.

Personal skills are stored in the user's profile under `%USERPROFILE%\.copilot\skills`. Use a personal skill when you want it available across repositories and branches without tracking it in GitHub. Project skills are stored in a repository's `.github/skills/`, `.claude/skills/`, or `.agents/skills/` directory.

== Generate a personal skill with Copilot

Define a focused writing capability with Copilot to create consistent guidance for recurring documentation work.

Use the `/create-skill` command in Copilot Chat to generate the skill directory and `SKILL.md` file. Describe the writing task, provide the resources you gather, and explain the behavior you want the skill to produce. Copilot generates the initial files and proposes the metadata, workflow, style rules, prohibited content, and final check.

For example:

[source,text]
----
 /create-skill
Create a skill for [describe the writing task].
Use these resources: [list the pages, instructions, examples, and terminology guidance].
Point out any behavior or outcome that is not supported by the resources.
----

When Copilot asks where to create the skill, choose the user or personal location. Treat the generated files as a draft. Review them, keep the accurate parts, add reference files when needed, and update the metadata or instructions before testing the skill.

Review and edit the generated `SKILL.md`, then save the approved content in the personal skill directory.

== Create a personal skill in VS Code

Use the Agent Customizations editor to create the personal skill through the VS Code interface. This is an alternative to using `/create-skill`; both methods create the skill on your local computer.

.Steps

. In VS Code, open the Command Palette and run *Chat: Open Customizations*.
. Select the *Skills* tab.
. Select *New Skill > User*.
. Enter a descriptive skill name, such as `user-focused-examples`.

VS Code saves the skill under `%USERPROFILE%\.copilot\skills`. On Windows, `%USERPROFILE%` refers to your user profile directory, such as `C:\Users\tonias`.

The personal skill directory uses the following path:

[source,text]
----
%USERPROFILE%\.copilot\skills\user-focused-examples\
----

Because this directory is outside the repository, Git does not track the skill.

VS Code creates a file named `SKILL.md` in the skill directory. If you use `/create-skill`, Copilot generates this file and may also create supporting directories or files. The filename must use this capitalization because GitHub Copilot looks for the skill instructions in this file.

[source,text]
----
%USERPROFILE%\.copilot\skills\user-focused-examples\SKILL.md
----

== Review the generated skill

Verify the skill’s guidance, output, and restrictions before relying on it.

Copilot generates the initial metadata and file structure. Review and revise the generated files instead of creating them from scratch.

Review the generated instructions and confirm that they:

* Describe the steps Copilot should follow for the specific writing task.
* Identify the source pages and other resources Copilot should read.
* Define the required style and expected output.
* Identify content Copilot must not produce.
* End with a check that can be used to review the result.

In this example, the `user-focused-examples` skill instructs Copilot to read the target page and related documentation, create two imperative alternatives, avoid UI or procedural language, and state uncertainty instead of inventing behavior.

Keep the instructions specific to the task. Confirm that the skill includes only documented product behavior and uses requirements that can be checked.

== Best practices for reference files

Reference files are optional. Use them to separate detailed examples, terminology, and audience guidance from the core instructions so the skill is easier to maintain.

Use a `references` directory when the skill needs detailed guidance that would make `SKILL.md` difficult to scan. Reference files contain supporting information that GitHub Copilot can consult when it uses the skill. Copilot loads the supporting material when `SKILL.md` references it.

[source,text]
----
%USERPROFILE%\.copilot\skills\<skill-name>\
|-- SKILL.md
`-- references/
    |-- personas.md
    |-- examples.md
    `-- use-case-guidance.md
----

Keep the core purpose, workflow, required output, and restrictions in `SKILL.md`. Put detailed or specialized information in reference files, such as persona guidance, terminology, examples, or specialized product guidance. Link to each reference file from `SKILL.md` with a relative link. For example:

[source,markdown]
----
Use the [persona guidance](./references/personas.md) to select a credible user context.
----

Copilot can create these reference files when you request them during skill generation. Review each file and confirm that `SKILL.md` references it. Do not create reference files until the main instructions need them.

Keep the main `SKILL.md` focused on the skill's purpose, workflow, required style, prohibited content, and final check.

== Use a personal skill in Copilot Chat

After you create the skill, use it from the Copilot Chat view in VS Code. Personal skills are available across repositories and branches when you use the same VS Code user profile.

Complete or revise the generated `SKILL.md` file using the guidance in this topic.

. Open the documentation repository in VS Code.
. Open the Copilot Chat view.
. In the chat box, type `/` and choose the skill from the list.
. Provide the context and information required by the skill. The required inputs can differ between skills.
. Review the response against the skill's instructions and the relevant source material.

For example, you can invoke the `user-focused-examples` skill as follows. This example shows one skill's inputs; other skills can use different inputs:

[source,text]
----
/user-focused-examples
Target page: task-alerts-monitor.adoc
Capability: View alerts for storage resources
User goal: Understand which alerts need attention and why
Placement: Task lead
----

The example skill returns two concise alternatives. These alternatives are specific to `user-focused-examples`; another skill may return a different format.

NOTE: If a personal skill does not appear in the slash-command list, verify that it is under `%USERPROFILE%\.copilot\skills`, that the file is named `SKILL.md`, and that the frontmatter sets `user-invocable: true`. Reload VS Code after creating or moving the skill.

For example, a response might look like this:

[source,text]
----
Alternative 1: Identify storage alerts that require attention to maintain system health.
Alternative 2: Investigate storage alerts to determine which issues could affect operations.
----

You can invoke a skill for a single page or repeat the process for each section that needs its specialized guidance. Adjust the prompt to match the skill's purpose.

Verify the skill before using it regularly:

* Confirm that it appears when you type `/` in Copilot Chat.
* Test it with a real documentation page.
* Check the response against the source content and the skill's instructions.
* Confirm that the skill remains under `%USERPROFILE%\.copilot\skills` and outside the Git repository.

== Review and refine a personal skill

Refine the skill when its output becomes too broad, repetitive, or inconsistent with the intended writing task.

After testing the skill, use Copilot to review and improve it. Keep the skill's purpose and the resources it uses in mind while you make changes.

.Steps

. Open the personal skill's `SKILL.md` file from `%USERPROFILE%\.copilot\skills`.
. Open the Copilot Chat view.
. Ask Copilot to review the skill for unclear instructions, missing requirements, repeated content, or unsupported claims.
. Include the target documentation pages and other resources that the skill should use for its review.
. Compare Copilot's suggestions with the resources and keep only accurate suggestions.
. Edit and save `SKILL.md` with the changes you want to keep.

For example:

[source,text]
----
Review this existing skill for clarity and completeness.
Use the resources referenced by the skill and identify any unsupported instructions or outcomes.
Suggest focused changes without changing the skill's purpose.
----

Because the skill is stored under `%USERPROFILE%\.copilot\skills`, these changes remain on your local computer and are not tracked in the documentation repository.

== Troubleshoot personal skill problems

If GitHub Copilot does not use the skill, check the following:

* The directory is under `%USERPROFILE%\.copilot\skills` for a personal skill.
* The instruction file is named `SKILL.md`.
* The frontmatter starts and ends with `---`.
* The `name` value matches the skill directory name.
* The skill appears when you type `/` in Copilot Chat.
* The skill is outside the Git repository and does not appear as a file to commit.
