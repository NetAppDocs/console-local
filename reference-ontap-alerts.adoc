= ONTAP alerts reference in NetApp Console (local deployment)
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
This reference lists the ONTAP alerts that NetApp Console (local deployment) can monitor, organized by impact category.

== Severity mapping

The same EMS alert can appear as Critical, Warning, or Info, depending on the ONTAP event that caused it:

* *Critical*: Maps from ONTAP severities `alert`, `emergency`
* *Warning*: Maps from ONTAP severity `error`
* *Info*: Maps from ONTAP severities `notice`, `informational`
* *Other*: Passed through as-is

Dynamic mapping lets a single alert rule emit different severities depending on the runtime context of the EMS event.

The sections below group alerts by impact category and sort each table alphabetically by alert name.

== Availability alerts

These alerts can affect system, service, or data availability.

[cols="25,15,45",options="header"]
|===
| Alert name | Type | Description

| Aggregate isn't online
| Metric
| Some aggregates are offline. Volume creation could cause duplicate FSIDs.

| Antivirus server busy
| EMS
| The antivirus server is overloaded and can't accept additional scan requests.

| AWS credentials not initialized
| EMS
| A module attempted to access AWS IAM role-based credentials before they were initialized.

| Cloud tier unreachable
| EMS
| A storage node cannot connect to Cloud Tier object store API. Some data will be inaccessible.

| Disk failure
| Metric
| A disk has failed, is being sanitized, or is in Maintenance mode.

| Disk out of service
| EMS
| A disk was taken out of service due to failure, sanitization, or maintenance.

| Disk shelves power supply removed
| EMS
| A power supply unit was removed from the disk shelf.

| FC target port commands exceeded
| EMS
| The number of outstanding commands on the physical FC target port exceeds the supported limit.

| Giveback of storage pool failed
| EMS
| This event occurs during the relocation of a storage pool (aggregate) as part of a storage failover (SFO) giveback, when the destination node cannot reach the object stores.

| HA interconnect down
| EMS
| The high-availability (HA) interconnect is down. Risk of service outage when failover is not available.

| InstanceDown
| Metric
| The monitored instance is unreachable and may be down or experiencing network issues.

| EMS
| A LUN was destroyed and is no longer accessible.

| A LUN was taken offline manually.

| One or more main unit cooling fans are in a warning state.

| EMS
| You have exceeded the maximum number of sessions allowed per user over a TCP connection.

| Max times open per file exceeded
| EMS
| You have exceeded the maximum number of times that you can open the file over a TCP connection.

| MetroCluster automatic unplanned switchover disabled
| EMS
| Automatic unplanned switchover capability has been disabled on this cluster.

| MetroCluster monitoring
| EMS
| The system health monitor alert is detected.

| NFSv4 store pool exhausted
| EMS
| A NFSv4 store pool has been exhausted.

| NetBIOS name conflict

| The NetBIOS Name Service has received a negative response to a name registration request, from a remote machine.

| No registered scan engine
| EMS
| The antivirus connector notified ONTAP that it does not have a registered scan engine.

| No Vscan connection
| EMS
| ONTAP has no Vscan connection to service virus scan requests. This might cause data unavailability if the scan-mandatory option is enabled.

| Non-responsive antivirus server
| EMS

| Nonexistent admin share

| NVMe namespace destroyed

| An NVMe namespace was taken offline manually.

| EMS
| An NVMe namespace was brought back online.

| NVMe-oF license grace period active
| EMS
| This event occurs on a daily basis when the NVMe over Fabrics (NVMe-oF) protocol is in use and the grace period of the license is active.

| NVMe-oF license grace period expired
| EMS
| The NVMe over Fabrics (NVMe-oF) license grace period is over and the NVMe-oF functionality is disabled.

| NVMe-oF license grace period start
| EMS
| The NVMe over Fabrics (NVMe-oF) configuration was detected during the upgrade to ONTAP 9.5 software.

| Object store host unresolvable
| EMS
| The object store server host name cannot be resolved to an IP address.

| Object store intercluster LIF down
| EMS
| The object-store client cannot find an operational LIF to communicate with the object store server.

| Object store signature mismatch
| EMS
| The request signature sent to the object store server does not match the signature calculated by the client.

| Service Processor heartbeat missed
| EMS
| ONTAP is not receiving an expected heartbeat signal from the Service Processor (SP).

| Service Processor heartbeat stopped
| EMS
| ONTAP is no longer receiving heartbeats from the Service Processor (SP).

| Service Processor offline
| EMS
| The Service Processor (SP) is offline.

| Shelf fan failed
| EMS
| The indicated cooling fan or fan module of the shelf has failed.

| SnapMirror lag time is high
| Metric
| The SnapMirror relationship is more than one hour behind its expected update schedule.

| Storage switch power supplies failed
| EMS
| There is a missing power supply in the cluster switch. Redundancy is reduced.

| System cannot operate due to main unit fan failure
| EMS
| One or more main unit fans have failed, disrupting system operation. This might lead to a potential data loss.

| Too many CIFS authentication
| EMS
| Many authentication negotiations have occurred simultaneously. There are 256 incomplete new session requests from this client.

| Volume state offline
| Metric
| The volume has been taken offline.

| Virus detected
| EMS
| A Vscan server reported that a file might be infected with a virus.

== Capacity alerts

These alerts indicate storage consumption or capacity pressure.

[cols="25,15,45",options="header"]
|===
| Alert name | Type | Description

| FabricPool space usage limit nearly reached
| EMS
| The total cluster-wide FabricPool space usage of object stores from capacity-licensed providers has nearly reached the licensed limit.

| FabricPool space usage limit reached
| EMS
| The total cluster-wide FabricPool space usage of object stores from capacity-licensed providers has reached the license limit.

| Node root volume space low
| EMS
| The system has detected that the root volume is dangerously low on space.

| QoS monitor memory maxed out
| EMS
| A QoS subsystem's dynamic memory has reached its limit for the current platform hardware.

| Volume full
| Metric
| The volume is over 90% full. Free up space or add capacity to prevent write failures.
|===
