= Monitor snapshot reserve consumption on a volume in NetApp Console Local
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
When snapshot copies accumulate faster than expected, they can overflow the snapshot reserve and begin consuming space from the volume's data area. Use the Workload Analyzer to track snapshot space consumption over time and project when the reserve will be exceeded.

.Steps

. In the NetApp Console Local, navigate to *Workload Analyzer*.
+
Alternatively, from the storage inventory, select a volume and click *Analyze*.

. In the *Volume* field, search for and select the volume you want to investigate.

. Set the *Time Range* to *Last 7 days* to capture enough snapshot growth history for a meaningful projection, then click *Analyze*.

. Scroll to the *Capacity Analysis* section.

. Open the *View* dropdown and select *Snapshot View*.
+
The chart switches to show snapshot space only. The snapshot reserve appears as a horizontal reference line, and snapshot used capacity is shown as an area below it.

. Use the component picker to confirm both *Snapshot Reserve* and *Snapshot Used* are enabled.

. Enable *Show Forecast*.
+
The chart extends beyond the current time with a dashed projection line. An insight message appears when the forecast indicates snapshot consumption will exceed the reserve, along with an estimated number of days until overflow.

. Hover over a point on the chart to see the snapshot details at that time:
+
* Snapshot reserve size
* Snapshot space currently used and its percentage of the reserve
* Number of snapshots
* Age of the oldest snapshot
* Whether reserve overflow has already occurred

.Results

When snapshot consumption exceeds the snapshot reserve, snapshots begin consuming space from the volume's data area. This reduces available space for active data and accelerates the rate at which the volume reaches its capacity thresholds.

If the forecast shows reserve overflow is approaching, consider the following actions:

* Increase the snapshot reserve percentage to accommodate current snapshot retention settings
* Reduce the snapshot retention schedule to limit the number of snapshots held at any time
* Delete old snapshots manually to reclaim space immediately
* Increase the overall volume size to provide more headroom for both data and snapshots
