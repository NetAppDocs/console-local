= Provision storage with AI-assisted (agentic) workflows in NetApp Console local deployment

// Jira: SPSPM-3325, SPSPM-3304

In NetApp Console local deployment, request storage conversationally while preserving approved storage-class intent and role-based controls across managed fleets.

include::_include/ai-preview.adoc[]

.Required access roles
Super admin, Organization admin, Folder or fleet admin, or Storage admin. Your AI-assisted actions are limited by the same role-based access as UI-based actions. link:reference-iam-predefined-roles.html[Learn about access roles].

Agentic provisioning requires an LLM integration to be configured and available in your NetApp Console local deployment environment.

== Before you begin
Prepare fleets, systems, storage classes, and LLM access so the assistant can generate plans within approved provisioning boundaries.

* Ensure LLM integration is configured and enabled for your NetApp Console local deployment.
* Ensure the target fleet contains discovered storage systems.
* Ensure storage classes are configured and associated with the fleet so the assistant can propose class-aligned plans.

.Steps

. Open the NetApp Console assistant.
. Describe what you need in plain language (for example, protocol, size, environment, performance intent, and target fleet if applicable).
. Review the proposed plan, including:
The selected fleet and target system placement, if applicable.
The selected or recommended storage class.
The key settings that will be applied, such as capacity behavior, protection schedule, security requirements, and QoS-related intent, if shown.
. Confirm or adjust the plan.
If the plan selects an unexpected class or placement, specify the desired class, fleet, or constraints and regenerate the plan.
. Approve execution to provision the workload.
. Verify the created resource in the storage inventory and confirm it is associated with the intended storage class for ongoing drift monitoring.
