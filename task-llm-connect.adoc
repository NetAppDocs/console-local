= Connect your LLM and enable the NetApp Console assistant in NetApp Console local deployment
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Connect a supported LLM endpoint to make governed natural-language storage guidance and operations available to NetApp Console local deployment users.

include::_include/ai-preview.adoc[]

.Required access roles
Super admin or Organization admin. link:reference-iam-predefined-roles.html[Learn about access roles].

After setup, users open the Console assistant from the dashboard and choose an access mode:

* In *Read only* mode, the assistant answers questions and provides guidance without making changes.
* In *Read/write* mode, the assistant can act on storage infrastructure. It shows details for review and confirmation before each change. For asynchronous operations, such as volume creation, it creates a job that users can check from the assistant.

To connect your LLM, select a provider path, enter endpoint details and API key, and then select a model in *Administration > AI Tools*. Assistant actions stay within your storage policies and role-based access controls.

== Gather what you need before you connect an LLM

Prepare provider credentials and endpoint access so the Console assistant can operate within your organization’s configured governance boundaries.

* Your provider type decision: OpenAI, OpenAI-compatible, or Anthropic, as supported by release and endpoint. 
* A valid API key for the provider path you select.
* The endpoint URL for your provider path.
* Your user name or ID for the LLM provider account, if required.
* Network access from Console local deployment to the selected endpoint.


link:reference-llm-supported-models.html[Learn about supported LLM providers and models in NetApp Console local deployment].


== Connect an LLM to NetApp Console local deployment

Enable assistant capabilities through a validated provider configuration while retaining administrative control over endpoint credentials.

.Steps
. Log in to the NetApp Console local deployment.
. Select *Administration > AI Tools*.
. Select the menu, and then select *Edit*.
. In *Provider type*, select a provider type.
+
link:concept-llm-integration.html[Learn about LLM integration in NetApp Console local deployment].
. If prompted for a provider endpoint, enter the endpoint URL for the provider path you selected.
. In the *User name* field, enter your user name or SSO ID if your provider path requires it.
. In the *API key* field, paste the API key from your selected provider path.
. Select a model from the list.
. Review the configuration, and then select *Save*.
+
Review the provider type, endpoint URL, API key, and selected model before saving the configuration.

== Verify that LLM integration works

Confirm assistant availability and approval behavior so users can rely on the configured integration for governed operations.

.Steps
. Open the *Console assistant* in *Read only* mode and run a basic query.
. Open the *Console assistant* in *Read/write* mode and confirm that storage-changing actions require user confirmation before execution.
. Verify that the users who need action workflows have the required role-based access controls.

After you complete validation, users can open the Console assistant from the dashboard and describe tasks in plain language. link:task-console-asst-use.html[Learn about using NetApp Console assistant].

== Protect credentials and monitor LLM usage

Protect LLM credentials and monitor provider activity to reduce unauthorized use of the integration and support organizational governance.

* Use a dedicated API key for Console local deployment integration when possible.
* Rotate API keys according to your organization policy.
* Monitor provider-side API usage and alerts according to your organization's governance requirements.
