= Manage fleet access assignments in NetApp Console (local)
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Use this fleet-centric workflow to manage access for a specific folder or fleet. Assign roles to set permissions for fleet resources, and modify or remove access when responsibilities change.

If you want to manage all roles for one member across multiple fleets, use the member-centric workflow. link:task-iam-manage-roles.html[Manage member access].

.Required access roles
You must have the Organization admin role to manage member access across all folders and fleets. Folder or fleet admins can manage member access only for folders and fleets that they administer. link:reference-iam-predefined-roles.html[Learn about access roles].

NOTE: Create your folders and fleets before assigning member access. link:task-iam-manage-folders-fleets.html[Learn how to create folders and storage fleets].

== Understand how folder and fleet access works

The NetApp Console (local) uses a role-based access control (RBAC) model to manage member permissions. You assign predefined roles to members at the organization, folder, or fleet level.

=== Role inheritance

When you assign a role at a higher level in the resource hierarchy, it is automatically inherited by all resources within that scope:

* *Organization level*: The member has that role across all folders and fleets.
* *Folder level*: The member inherits that role for all fleets and subfolders within the folder.
* *Fleet level*: The member has access only to the resources within that fleet.

For example, assigning the Storage admin role at a folder level gives the member storage administration access to all fleets within that folder.

Members can have multiple roles within the same fleet and across different folders and fleets. For example, you might assign a member the Storage admin role for a production folder (which gives them access to all fleets in that folder) and the Storage viewer role for a separate development fleet.

NOTE: You cannot change member access at lower levels if it is inherited from a folder or the organization. Change the member's permission at the higher hierarchy level to change access.

== View members assigned to a folder or fleet

View which members have access to a specific folder or fleet.

.Steps

. Select *Administration* > *Identity and access*.

. Select *Organization*.

. From the Organization page, navigate to a folder or fleet in the table, select image:icon-action.png[An icon with three dots] and then select *Edit folder* or *Edit fleet*.

. Select *Access* to view the members who have access to the folder or fleet.

== Manage one member across multiple scopes

This page is fleet-centric. If you need to add roles, change roles, or remove one member across multiple folders or fleets, use the member-centric task: link:task-iam-manage-roles.html[Manage member access].

== Modify member access from a folder or fleet

You can also manage member access directly from the folder or fleet in the Organization page.

.Steps

. From the Organization page, navigate to a folder or fleet in the table, select image:icon-action.png[An icon with three dots] and then select *Edit folder* or *Edit fleet*.

. Select *Access* to view the list of members who have access.

. Modify member access:
+
* *Add a member*: Select the member that you'd like to add to the folder or fleet and assign them a role.
* *Change a member's role*: For any members with a role other than Organization admin, select their existing role and then choose a new role.
* *Remove member access*: For members who have a role defined at this folder or fleet, you can remove their access.

. Select *Apply*.
