Use the Workload Analyzer to view a single volume's behavior over time. You can investigate performance degradation, capacity trends, and resource contention without needing deep ONTAP expertise.

== What the Workload Analyzer does

Use the Workload Analyzer to correlate metrics from a single volume across six sections so you can identify root causes quickly. Select a volume and a time range to view events, performance, and capacity together within the same window. This view can help you determine whether storage is the likely source of an application issue or whether another layer, such as networking, is causing the problem.

After you identify a root cause, you can act directly from the analyzer. When automated options are available, Console (local) provides Fix-It recommendations with guided steps or one-click remediation.

== How to access the Workload Analyzer

You can open the Workload Analyzer in several ways:

* *From the storage inventory*: Select a volume and click *Analyze*. The analyzer opens with the volume pre-filled and a default time range of the last two hours.
* *From a volume detail page*: Click *Analyze* to open the analyzer pre-filled with the current volume and a default time range of the last two hours.
* *From an alert detail page*: Click *Investigate with Analyzer*. The analyzer pre-fills the affected volume and shows the last 10 days of data by default, so you start your investigation in context without adjusting any settings.
* *From the menu*: Navigate directly to the Workload Analyzer, search for a volume, set a time range, and click *Analyze*.
* *From other inventory views*: You can also start analysis from supported workload inventory pages, including LUN, NFS share, SMB/CIFS share, and related workload views.
* *From the Virtual Machines page*: Select a datastore object and start workload analysis directly from that object.

== Analysis areas

Use these six sections to investigate a volume:

Volume selection::
Lets you choose the volume and time range to investigate so all charts and events align to the same workload and analysis window.

Event timeline::
Shows current and historical configuration changes, warning alerts, and critical alerts for the selected volume during the analysis window. Use this section to correlate "what changed" with changes in performance or capacity behavior.

Latency analysis::
Shows volume latency over time. You can view latency as a total or break it down by delay center—network, data processing, aggregate operations, cluster interconnect, and others. If the volume uses a QoS policy, the analyzer displays the policy's maximum and minimum latency limits as reference lines so you can see how close the workload is to a throttling threshold. Toggle the forecast to project whether latency is trending toward a warning or critical threshold.

Throughput analysis::
Shows IOPS and MB/s over time, with an optional read/write/other breakdown. If the volume uses a QoS policy, the analyzer displays IOPS and throughput limit lines. Toggle the forecast to project whether demand is trending toward QoS limits.

Resource utilization::
Shows how busy the nodes and aggregates serving the volume are during the analysis window. The analyzer plots each resource as an independent line rather than stacking values, so you can identify whether a specific node or aggregate is a contention source. Toggle the forecast to project whether any resource is trending toward a high-utilization threshold.

Capacity analysis::
Shows how physical space and available space in the volume have changed over time. Hover to see a storage efficiency breakdown including deduplication, compression, and compaction savings. Toggle the forecast to project when the volume will reach warning or critical capacity thresholds. Switch to the snapshot view to see how snapshot space is tracking against the configured snapshot reserve.

== Forecast

Use the forecast toggle in each analysis section to extend the chart timeline beyond the current time and project future values based on the observed trend. A dashed line distinguishes forecast values from actual data. The analyzer also displays an insight message when the forecast indicates that a threshold breach is likely, along with an estimated time to breach.

== Recommended investigation flow

Use the four Workload Analyzer pages together:

* Start with this page to understand the analyzer entry points, sections, and overall investigation model.
* Use the latency investigation page when an alert, application complaint, or event timeline suggests a performance slowdown.
* Use the throughput investigation page when you need to understand demand patterns, QoS limit behavior, or read and write mix.
* Use the metrics reference to interpret QoS limits, resource utilization, capacity trends, snapshot reserve behavior, and forecast details while you investigate.
