= Investigate high throughput on a volume in NetApp Console (local deployment>
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
When a volume's workload is consuming more IOPS or throughput than expected, use the Workload Analyzer to examine demand patterns over time. The throughput analysis section shows IOPS and MB/s with an optional read, write, and other breakdown so you can identify which type of I/O is driving high demand and whether that demand is trending toward a QoS limit.

== Before you begin

* Ensure NetApp Console (local deployment) has already discovered the volume you want to investigate.
* Identify the approximate time window when the demand spike occurred so you can select the right analysis range.

.Steps

. In the NetApp Console (local deployment), navigate to *Workload Analyzer*.
+
Alternatively, from the storage inventory, select a volume and click *Analyze*.

. In the *Volume* field, search for and select the volume you want to investigate.

. Set the *Time Range* to cover the period of high demand, then click *Analyze*.

. Scroll to the *Throughput Analysis* section.

. Open the *View* dropdown and select *Breakdown (RWO)*.
+
The charts split into read, write, and other components for both IOPS and MB/s. This lets you determine whether demand is driven by read-heavy access patterns, write-heavy patterns, or a combination.

. Use the component picker to enable or disable the metrics you want to examine:
+
* *Read IOPS* and *Write IOPS* — operations per second by I/O direction
* *Read MB/s* and *Write MB/s* — throughput in megabytes per second by I/O direction
* *Other IOPS* and *Other MB/s* — metadata and other non-data operations
* *QoS IOPS Limit* and *QoS MB/s Limit* — policy ceilings that appear only when the volume uses a QoS policy
* *Cloud Throughput* — MB/s written to and read from the cloud, shown only for workloads that tier capacity to the cloud through FabricPool

. Hover over a peak in the chart to see the exact value and percentage breakdown for each component at that point in time.
+
The hover tooltip also shows the average I/O size (throughput divided by IOPS) for each category, which can indicate whether the workload is performing large sequential I/O or small random I/O.

. Enable *Show Forecast* to project whether current throughput trends will reach the QoS IOPS or MB/s limit.
+
If the forecast line is approaching a QoS limit line, ONTAP might throttle the workload soon.

. If you want to see aggregate demand without the breakdown, open the *View* dropdown and select *Totals*.
+
The totals view shows a single IOPS line and a single MB/s line, which is useful for a quick overall demand summary.

.After you finish

Use the throughput patterns you observe to decide what to do next:

* If read IOPS are very high relative to write IOPS, consider whether read-ahead settings or caching can reduce the load on the volume.
* If the workload is approaching or has reached the QoS IOPS or MB/s limit, use the QoS limit lines and related metric definitions in link:reference-workload-analyzer-metrics.html[Workload Analyzer metrics reference] to confirm throttling and decide whether you need to adjust the limit.
* If throughput is high and latency is also elevated, check the *Resource Utilization* section to determine whether the underlying node or aggregate is under contention. Use link:task-analyzer-volume-latency-investigate.html[Investigate high latency on a volume] together with link:reference-workload-analyzer-metrics.html[Workload Analyzer metrics reference] to compare throughput peaks, latency spikes, and resource utilization over the same period.
* If the analyzer shows rapid capacity or snapshot growth while demand is increasing, review the capacity and snapshot metrics in link:reference-workload-analyzer-metrics.html[Workload Analyzer metrics reference] to understand how that growth might affect the volume.
